Layer A intentionally carries 1.4.2 CLI, site, catalog and registry metadata. **Do not merge Layer A to main before npm 1.4.2 is successfully published and verified. Main auto-deploys.** This correction is the governing 1.4.2 release sequence and supersedes any earlier shorthand suggesting deployment or hosted registry alignment before npm publication.

2. After separate authorization, dispatch hosted `prepare-cli.yml` on the exact Layer A commit. The earlier hosted 1.4.1 qualification does not qualify new 1.4.2 bytes.
3. Review the immutable artifact, exact source SHA, workflow/run/artifact IDs, manifest and independent hashes.
4. After separate authorization, configure npm Trusted Publisher. GitHub secrets/variables remain unchanged during this checkpoint.
5. After exact artifact approval, create the annotated release tag directly on the approved Layer A commit, using the reviewed JSON approval.
6. Publish that exact prepared artifact through the hardened workflow, without rebuilding or repacking.
7. Verify public npm 1.4.2, `latest`, exact public tarball bytes/hash and provenance. Run the required public consumer verification.
8. Only after npm verification, separately authorize merging Layer A to main.
9. Verify production site and all hosted registry versions/bytes against the approved release.
10. Recreate Layer B on committed Layer A using the preserved ten-file patch; the old cumulative A+B worktree must not be committed as-is.
11. Separately approve, merge and deploy Layer B, then verify the typography UI and copied commands in production.
