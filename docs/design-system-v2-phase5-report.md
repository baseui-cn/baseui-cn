## Implementation details and limits

The committed Drawer wrapper placed Popup directly in Portal. Installed Base UI 1.9 `drawer/popup/DrawerPopup.js` explicitly diagnoses a missing Viewport as disabling swipe handling and touch scroll locking. The [official Drawer anatomy](https://base-ui.com/react/components/drawer) also requires that composition. This phase inserts the native Viewport around the existing Popup and consumes native swipe/snap variables in shell CSS. Root remains the original primitive alias; no gesture algorithm, focus manager, snap-point calculation or scroll-lock implementation is copied or replaced. The `side` prop still controls styling independently of Root `swipeDirection`; examples/documentation now specify matching directions. SwipeArea, snap-point and optional keyboard-provider QA live only in disposable fixtures; no speculative wrapper API is added.

DialogHeader/Footer no longer draw automatic dividers or independent surfaces. DialogBody is the normal bounded scroll owner; a plain composition without it can scroll the popup. Drawer uses popup scrolling so existing arbitrary children continue to work without a new body API. Its header/footer can scroll with long content, and their actions remain reachable. Applications requiring a pinned Drawer composer can compose Base UI directly; this phase does not invent that behavior.

A small `.tp-dialog_content` compatibility scope in modal CSS preserves the existing picker radius, inherited type, zero gaps/padding and non-scaled presentation, with the previous title/description typography. The picker continues owning its width, safe-area margins, dynamic height and scroll rules. At 320px its existing margin can be smaller than generic Dialog's 16px; that protected geometry is deliberate rather than a silent Time Picker redesign. Date/Time stylesheets and implementations are unchanged.

The 200% document-CSS-zoom check initially exposed Drawer's `100dvh` size escaping its fixed viewport. Combining dynamic units with percentage bounds, and deriving side height from the native viewport, fixes that shell result. Dialog, Alert, Drawer and Command fit in the final simulation. This is not native browser zoom acceptance. Phase 4's separately documented anchored-popup CSS-zoom positioning limitation remains outside this change; no positioning workaround was added.

91 protected tracked files are byte-identical to HEAD, including other UI families/styles, all theme ownership/distribution files, Date/Time, CLI implementation, package manifests/lockfile, `cn()` and previous V2 reports. The approved Command content is separately byte-identical. The disposable baseline's four wrapper files match actual HEAD, rather than reconstructed approximations.
